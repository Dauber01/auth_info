# PRD

## 用户需求

1. docs 是主要文档目录，保存所有业务信息。
2. docs/tasks 下每个任务有 PRD、原型图、供 AI 操作页面的测试 case、设计流程及实施前思考计划。
3. docs/status.md 汇总全部任务和可继续工作的任务记忆。
4. 根 tests 目录保存 API 级测试，使用 Python 调用接口。
5. 每轮代码修改完成后执行测试生成 skill，生成或更新有意义的测试用例。

## 验收标准

- AC-01：旧知识迁入 docs，AI 入口指向新来源；不再维护两份业务事实。
- AC-02：新任务命令创建六个步骤文档与页面用例集合，重复 ID 不覆盖原内容。
- AC-03：任务自动进入 status；校验可发现丢失步骤文件、失效链接、未登记任务。
- AC-04：Python API 测试可在隔离本机服务重复运行，包含成功、校验失败与鉴权失败。
- AC-05：generate-tests 被双 harness 共用，并在开发流程中要求修改后执行；测试映射到需求/行为。
- AC-06：注入和升级保留目标项目已有 docs、任务状态和 tests。

范围：开发范式和测试设施。没有新增业务页面、接口或生产部署操作。
